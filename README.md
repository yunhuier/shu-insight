# 上大知讯 · 课程项目最终版

“上大知讯”是一个本机运行的通知挖掘与推荐小应用。它把四个公开通知来源统一为结构化记录，再进行分类、时间抽取、关键词扩展、相关性排序和可解释展示。

> **非上海大学官方产品，信息以官网原文为准。**

当前版本以兴趣标签推荐和关键词查找为主：预置四站的真实通知，手动更新只访问上海大学官网和本科生院；研究生院、计算机学院使用本地库存，不再参与在线检查。随工程提供的固定预置包为 **74 条：正文已读取 53 条、仅列表可见 21 条**，日常更新后的数量以页面为准。旧的 12 条审阅快照仍保留，合成测试夹具绝不作为真实通知导入。共享预置包使用经过脱敏的公开标题和摘要；源码 ZIP 不包含个人运行数据库、原始 HTML、附件或密钥。已有本地数据库的历史原始记录可能仍保留，展示时会清理预览，不能据此声称历史库已全部脱敏；历史通知不能当作当前报名提醒。

## 1. 首次安装（Windows PowerShell）

需要 Python 3.11 或 3.12，推荐 3.12：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
```

使用 Python 3.11 时，把第一行改为 `py -3.11 -m venv .venv`。不需要激活虚拟环境，后续直接调用其中的 Python。导入真实预置库；首次使用时，请明确指定要使用的本地数据库路径（导入完全离线）：

```powershell
.\.venv\Scripts\python.exe scripts\import_official_preload.py --manifest data\official\preload-2026-10-25.json --database data\shu_insight.sqlite3
```

首次导入新数据库应显示 `imported=74`、`rejected=0`。预置通知保留原有来源、发布时间和证据层级，不把导入时间当成官网最新核实时间。重复导入不会添加同一原文的重复记录，也不能用旧库存降级已有的新正文；已确认附件型条目不重新放回通知流。导入不清空原有数据。`seed_demo.py --reset` 只供隔离测试，不能用于正常使用的数据。如果以前设置过 `SHU_NOTICE_DATABASE_PATH`，请确认应用使用的数据库与导入路径一致。

## 2. 启动

完成首次安装和数据导入后，在解压后的 `shu-insight` 文件夹双击 `start.bat`。它会启动本机网站并打开浏览器。使用时保持启动窗口运行。若 8501 已被旧版占用，先关闭旧版的启动窗口，再启动这一版。

也可以在工程根目录用 PowerShell 启动：

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address 127.0.0.1 --server.port 8501 --server.headless true --browser.gatherUsageStats false
```

在工程根目录运行上述命令，手动打开 [本机网站](http://127.0.0.1:8501)。保持终端运行，按 `Ctrl+C` 停止；下次只需重新执行启动命令。也可以使用便捷脚本（若执行策略允许）：

```powershell
.\run_local.ps1
```

直接调用 Python 不需要激活环境，也不需要修改 PowerShell 执行策略。应用包含：

- 左侧提供兴趣标签、关键词查找、两站手动更新和各来源本地数量；正文已读取与仅列表可见分别计数。
- “为你推荐”按兴趣与关键词的匹配证据排序；“全部通知”可按时间浏览，输入自定义关键词时实际筛选通知。
- 左侧“我的画像”提供通用排序、聚类画像和固定画像。点击文章标题或“查看官网原文”会打开官网，并记录该篇文章。至少点开 10 篇不同文章后，聚类画像根据这些文章的标题、已收录摘要与主题标签做 TF-IDF 字符 n-gram + K-means 聚类，以最近点开的文章所在类别归纳阅读兴趣，参与推荐排序；画像的学历、年级、学院、专业由全部已读文章按时间衰减加权投票得出，不再只看最近一个簇。同一篇无论点击多少次都只计一篇，两种浏览方式共用本机阅读记录。刷新页面、搜索和切换画像不会增加阅读篇数。旧搜索记录保留，但不作为阅读样本。
- 画像排序里的“受众契合”由两部分合成：结构契合（通知是否明确面向你的培养层次、年级、学院、专业，按 0.7 计）与主题契合（通知的主题标签与画像主题的重合度，按 0.3 计）。通知没写适用对象、画像也没有主题时，该维度不参与总分，其余权重按比例归一，不再用固定 0.5 占位。
- 推荐卡片可展开「为什么排在这里？」查看各项排序分数，受众契合会拆出结构契合与主题契合。

推荐卡片依次标为“直接相关”“可能适用”“其他通知”，并展示实际关键词、明确适用对象等依据；没有明确匹配证据的卡片也保留，方便浏览。标签匹配不代表官网已确认你的申请资格。来源与时效等权重用于同层内排序，不显示为内容“相关度”百分比。所有真实卡片均可浏览，不设首屏条数上限。

仅列表可见的通知不提供正文摘要或结构化详情；有标题关键词命中时标“仅标题匹配，正文待读取”，最多进入“可能适用”，无命中则不声称标题匹配。已过截止时间的条目会标为“历史通知”，不能作为当前报名或办理提醒；请通过卡片的“查看官网原文”核对条件与后续信息。

测试演示记录标题带有 `[演示]`，原文链接使用保留域名 `demo.invalid`，不能进入已核实的真实通知视图。

### 单条通知 RAG 问答

每张真实通知卡片右下角有“问问这条通知”。点击打开小窗，在“DeepSeek 设置”中填写官方 API Key，再输入问题并点击“发送问题”。Key 仅保存在当前浏览器会话，不写入工程文件或数据库；也可在启动环境设置 `DEEPSEEK_API_KEY`。模型默认 `deepseek-flash`，可用 `DEEPSEEK_MODEL` 覆盖。配置名与接口按 [DeepSeek 官方文档](https://api-docs.deepseek.com/) 核对；`.env.example` 仅是示例，程序不会自动读取 `.env`。

实现为 BM25 检索加 DeepSeek：当前通知固定作为首要资料，再按问题选择最多两条已收录相关通知。默认勾选“读取官网全文”，发送问题时访问这些记录的官网原文，将清理后的正文分段，再检索最多五段相关内容交给模型；不会只取卡片摘要。取消“同时参考相关通知”可只问当前通知。

全文读取覆盖四个已配置来源的公开 HTML 正文，沿用原有访问规则、超时与请求间隔。正文成功后在当前会话缓存15分钟，失败短暂缓存60秒；“清除全文缓存”后下次发送会重读。缓存仅在会话内存中，不保存原始网页或修改通知数据库。读取失败会明确显示原因和“本次使用已收录摘要或标题”，不把摘要标为全文；PDF等附件暂不解析。这里只读取当前及已收录相关记录的原文，新通知仍通过更新进入候选库，不进行全网搜索。展开“查看回答依据”可见官网全文片段、来源与读取时间。

只有明确点击“发送问题”才读取官网并调用一次模型 API；打开/关闭弹窗、搜索、切换新闻和普通刷新不会触发这些请求，模型 API 不自动重试。请求会将问题、最近三轮对话和检索片段发送到 DeepSeek，使用该 Key 所属账户的 API 额度。每条新闻的会话分别保存，已收录记录变化时重置；可用“清空本条对话”清除当前新闻的问答。页面显示引用依据仍需要用户核对，引用编号检查不等于已经证明每个回答事实正确。

## 3. 合规的实时更新（可选）

打开、刷新页面、切换兴趣标签或关键词和读取状态都不会请求学校网站。运行应用后，可按以下步骤手动检查：

1. 在侧栏“更新通知”中点击更新按钮；仅上海大学官网和本科生院参与本轮检查。
2. 只有点击按钮才执行一次官网检查；程序会先核验 robots 和来源访问规则，不会在后台自动更新。
3. 页面根据实际来源、读页与候选处理事件展示进度，不推算虚假的完成比例；结束后核对新增/更新结果。研究生院与计算机学院的旧连接失败不作为本次结果，也不会自动重试。

如希望在请求头中提供可联系的邮箱，可选地在启动前设置环境值（不再提供侧栏输入框）：

```powershell
$env:SHU_NOTICE_CONTACT = "your-email@example.com"
.\run_local.ps1
```

有效邮箱只在主动点击时加入请求头；留空或无效格式不会加入，也不写入数据库、状态、日志或 Git。关闭、重开及刷新不会继续采集。

采集器有超时、有限重试、单来源熔断和来源隔离。四站真实记录仍可浏览，日常手动更新只允许前两个入口及其配置中的同域路径：

- 上海大学官网：`https://www.shu.edu.cn/tzgg.htm`
- 上海大学本科生院：`https://bksy.shu.edu.cn/index/tzgg.htm`
- 上海大学研究生院（仅本地库存）：`https://gs.shu.edu.cn/xwlb/sy.htm`
- 上海大学计算机工程与科学学院（仅本地库存）：`https://cs.shu.edu.cn/xxgk/tzgg.htm`

每次点击的**每个在线来源**最多读取 5 个已审阅列表页、进行 40 次**物理 HTTP 尝试**（两站合计最多 80 次）。robots、304、重定向、失败连接和重试均计入尝试；同主机相邻尝试至少间隔 2 秒。40 次尝试不代表新增 40 条通知。两站依次检查，预算用尽后不会后台续跑。

两个在线来源沿用已审阅的“下页”链接分页：只跟随当前页面上唯一的该链接，核验目标仍在栏目范围；每次最多读 5 页，不推算页码，也不代表检查全部历史栏目。链接或结构未通过核验时停止并报告部分检查。代码测试只验证本地解析和边界，实际能否读取由每次按钮更新的结果确认。配置超过 90 天未复核时仍跳过该站抓取。

预算不足、暂时失败或本轮超过 32 条详情候选时，未完成的 URL 留在本地队列，每站最多 200 个、有效期 90 天。未读正文的积压先处理，本轮新发现其次，已有正文的复核最后，共享候选上限。只有 URL 的积压不进入通知中心；实际列表已出现的条目可显示标题、原文链接和“正文尚未读取，暂无摘要”，缺少日期时明确标未知，与正文记录分别计数。队列不会自动继续，也不再提供侧栏清空按钮；下一次仍需主动点击更新。

仅 URL 候选必须先在本次已解析官网列表中出现，或已有仍有效的列表卡片证明，才会请求正文；裸 URL 不会直接变成通知。后续列表页失败时，前面已核验且未被后页拒绝的列表条目会保留卡片并加入待处理队列，不会提前请求正文。已解析记录按可重试队列、本轮列表、可选历史的顺序复核。本轮列表每次点击都可复核；其他历史只有在最近 90 天发布且至少 24 小时未核实时才使用剩余名额，无发布日期时以最近核实时间作近期代理，不声称是首次核实时间。可选历史因 32 条上限延后不会计为跳过或部分检查；本轮必需候选未处理完、分页未完成或物理请求预算用尽仍会报告部分检查。

更新结果默认显示正文、仅列表及待处理条数；展开技术计数可查看 robots、列表、正文、重试的独立物理请求数（四项合计等于请求总数）。重试只计入重试项。升级到数据库 v5 时先自动生成并校验可恢复备份，已有通知、画像和历史版本保留，新计数默认为零。

“数据更新状态”的含义：

| 显示内容 | 应如何理解 |
| --- | --- |
| 本会话最近一次更新点击结果 | 本会话按钮操作的结果；`success` 表示完成本轮范围，`partial` 表示部分检查或部分写入，`failed` 表示未完成检查，`concurrent_skipped` 表示已有更新运行、本次跳过，不是成功更新。新增数与更新已有记录的数量分别显示。 |
| 最近一次手动点击 / 结束时间 | 数据库保存的运行历史，重开会话后仍可读取；尚无结束记录可能是其他页面仍在更新或运行中断，读取状态不会启动或修复该运行。 |
| 最近成功读取栏目页 | 最近一次成功解析列表的时间，不证明正文已全部核实，也不抹去后来失败。 |
| 最近本轮范围完整处理 | 完成本轮实际读取的配置范围的最近时间；若只读到一页，不能视为已检查五页。旧成功记录未记录范围时单独显示为“历史成功检查”，不能当作已知范围完成。 |
| 最近尝试读页数 / 物理请求数 / 跳过原因 | 最近尝试实际读取和消耗的数量，以及固定安全原因；禁止访问、robots 不可用、结构变化、预算用尽等均不能当作没有新通知。 |
| 检查范围 / 安全限制或结果 | 检查范围只根据本轮实际读取的栏目页显示；未读取栏目页时不会把访问失败写成分页失败。浏览器能打开网页并不证明本机程序已读取 `robots.txt`。 |
| 当前未核实队列 / 最近尝试结束时积压 | 分别是当前与最近尝试结束时的仅 URL 候选数量，不含已有列表卡片的重叠项；“当前待正文处理”另计全部待处理项。清空队列后历史值仍可能非零。 |

robots.txt 返回 404/410 时，依据 [RFC 9309 第 2.3.1.3 节](https://www.rfc-editor.org/rfc/rfc9309.html#section-2.3.1.3)按未发布 robots 规则处理，继续检查配置中的公开栏目，并记录“robots.txt 未发布”。401/403、429、其他 4xx、5xx、连接失败、跳转未核验、HTML/登录页和无效规则仍停止该来源。仅保存固定原因码，不保存 robots 正文、响应头或请求联系邮箱。旧失败记录保留原结果，新状态由下一次手动点击取得。

官网公开文章不因“录取”“奖学金”“处分”等主题词而整篇拒收。正文预览先去除名单表格、逐人结果和直接标识；手机号、邮箱、学号、证件号等会遮盖，剩余的非个人性说明才用于摘要、时间、适用对象和分类。通知标题和版本记录也使用脱敏文本。若已读取的正文没有可靠的安全摘要，卡片会标“正文已读取，摘要未生成”，并提示查看官网原文；不会以标题编造摘要。超长无标点段落会生成带省略号的摘要预览，不因无法选出完整短句而丢失通知。

程序不会绕过登录、验证码、robots 明确禁止规则、403、429 或访问控制，不下载 PDF/Word/Excel/图片等附件；确认仅为附件的列表条目会从通知流撤下。规则无法保证识别所有个人结果措辞，新写入条目仍需人工核对；不要把不确定的个人结果预览当作可公开展示的内容。单篇正文结构无法解析时会跳过该篇并继续检查同站其他通知，栏目列表结构异常仍会停止该来源。只有取得合规的官网公开 HTML 正文后，才能记为 `verified_live`；失败时不会补造通知或把旧快照改称实时核实。仓库的 12 条已审阅快照也不能证明当前四站网络成功。若学校明确禁止自动访问，应停止使用实时更新，只使用逐条核对的离线官网快照。

## 4. AI 与语义模型

通知推荐和关键词排序在本机完成，不调用外部 AI；设置 `SHU_NOTICE_AI_ENABLED` 不会改变界面排序。“问问这条通知”是独立的 DeepSeek 问答功能，只有填写 Key 并发送问题时才调用模型，具体用法见前面的“单条通知 RAG 问答”。仓库另保留旧 AI 增强器的实验模块和测试脚手架，它们不参与当前界面的推荐排序。

语义模型也是可选能力，不会在安装或测试期间自动下载：

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[semantic]"
.\.venv\Scripts\python.exe scripts\cache_semantic_model.py --destination data\models\bge-small-zh-v1.5 --yes
$env:SHU_NOTICE_SEMANTIC_MODEL_PATH = (Resolve-Path data\models\bge-small-zh-v1.5)
```

通知中心使用关键词匹配、兴趣扩展与时效、来源等分数排序。聚类画像使用 TF-IDF 表示已打开的文章，语义后端用于开发者实验。评估脚本只加载已缓存的本地模型目录。模型不存在时，`semantic` 实验标记为 `unavailable`，组合实验记录使用 TF-IDF 回退。

```powershell
.\.venv\Scripts\python.exe scripts\run_evaluation.py --allow-mini-fixture --dataset tests\fixtures\annotations\mini_frozen_set.jsonl --output data\test-evaluation.json
```

预置库用于本机展示，其中的仅列表记录不算已解析正文，更不能把库存数量当作人工标注量。正式评估仍须取得足量合规、逐条已核实的通知，并完成 150–250 条人工标注，再导出、复核、冻结并运行实验：

```powershell
.\.venv\Scripts\python.exe scripts\export_annotation_queue.py --database data\shu_insight.sqlite3 --output data\local\annotation-queue.jsonl
# 人工补齐 schema 要求的标签、重复簇、证据修正和 reviewed_by=human
.\.venv\Scripts\python.exe scripts\freeze_annotations.py data\local\reviewed.jsonl data\annotations\frozen.jsonl --database data\shu_insight.sqlite3
.\.venv\Scripts\python.exe scripts\run_evaluation.py --dataset data\annotations\frozen.jsonl --output data\evaluation.json
```

标注队列只导出已读取正文或已审阅快照的通知；仅列表可见和仅 URL 待处理的条目不进入正式评估。`--database` 会逐行核对标注 ID、来源、官网原文 URL 和标题是否与当前已核实通知一致，并记录当时的证明摘要。冻结集的 SHA-256 清单和来源证明侧文件可以检测本地文件不一致，但不能独立证明人工复核真实发生，也不能防止有意改写全部本地文件。保留的评估模块会再次核对证明，当前网站不展示实验报告。

评估脚本按重复簇切分训练/验证/测试集：TF-IDF 只在训练集拟合，去重阈值只在验证集选择，所有报告指标只来自冻结测试集。分类、实体抽取、相似度去重和排序都调用项目实际实现，消融实验会关闭对应的真实组件。预置库和程序测试不能替代人工冻结集的正式评估。
