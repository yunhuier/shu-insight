# 组员协作与运行

这份说明适用于收到“上大知讯”源码包、准备参与开发或在自己电脑演示的组员。工程是本机 Streamlit 应用；源码、Python 环境和运行数据库是三件不同的东西。

## 交接工程

首次交接使用 `scripts/package_project.py` 生成的 ZIP。发送方先完成并检查代码，再在工程根目录执行：

```powershell
.\.venv\Scripts\python.exe scripts\package_project.py --output artifacts\shu-insight-teammates.zip
```

已有同名 ZIP 时请换一个文件名。代码修改后需要重新打包；旧 ZIP 不会自动更新。把生成的 ZIP 通过你们选定的渠道交给组员即可，本脚本不会上传或发送任何文件。

ZIP 顶层为 `shu-insight` 文件夹，包括：

- `app.py`、`src/`、`config/`、`pyproject.toml` 与启动脚本；
- 本说明、README、离线导入和开发辅助脚本；
- `data/official/preload-2026-10-25.json` 真实预置数据；
- 测试源码和离线夹具，另含测试所需的历史快照与明确标注的演示数据。

ZIP 不包含已有虚拟环境、运行数据库、API Key、`.env`、本地标注、缓存、备份或其他课程工程。组员各自创建环境和数据库。测试里的合成记录仅用于测试；首次导入必须使用真实预置包。

## 组员第一次运行（Windows）

安装 Python **3.11 或 3.12**。将 ZIP 完整解压到自己选择的目录，不要直接在压缩包预览中打开应用。打开解压后的 `shu-insight` 文件夹，确认能看到 `app.py`、`pyproject.toml`、`src` 和 `data`，在该文件夹打开 PowerShell。

以下命令都在这个工程根目录执行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe scripts\import_official_preload.py --manifest data\official\preload-2026-10-25.json --database data\shu_insight.sqlite3
```

只有 Python 3.11 时，将第一行改为 `py -3.11 -m venv .venv`。如果安装时没有 `py` 命令，可先用 `python --version` 确认当前解释器为 3.11 或 3.12，再用 `python -m venv .venv` 创建环境。其余步骤仍用明确的 `.venv\Scripts\python.exe` 路径。

上述步骤依次创建 Python 环境、联网安装依赖、离线导入通知。首次导入预期显示 `imported=74` 和 `rejected=0`。

安装和导入完成后，双击工程根目录里的 `start.bat`，浏览器会自动打开本机网站。使用时保持启动窗口运行，按 `Ctrl+C` 停止。以后直接双击同一个文件即可。首次可浏览 74 条，其中正文已读取 53 条、仅列表可见 21 条。若浏览器没有自动显示首页，可手动打开 [本机网站](http://127.0.0.1:8501/)。

## 以后怎样使用网站

每个组员都在自己的工程目录中启动应用，再访问自己的 `http://127.0.0.1:8501`。`localhost` 和 `127.0.0.1` 都指浏览器所在的这台电脑；发给别人这个链接，并不会让别人连接到你的电脑。

源码修改经合并或重新交接后，组员运行的就是更新后的代码。若 `pyproject.toml` 的依赖变了，先再次执行 `pip install -e .`。各组员自己的通知数据库、更新历史和环境设置不会随着源码同步；收到新源码时保留自己的 `.venv` 与 `data/shu_insight.sqlite3`，不要用他人的整个运行目录覆盖。

当前没有公网网址、共享账号或共享数据库。如果只是让组员操作和展示，各自在本机运行即可。兴趣标签与关键词用于推荐和查找；侧栏展示各来源本地数量。更新按钮只检查官网、本科生院；研究生院和计算机学院使用库存。打开或刷新网站不会自动访问学校网站。

在通知卡片上点击标题或「查看官网原文」，每篇文章记录一次。累计打开 10 篇不同通知后，可在「我的画像」选择「聚类画像」，按阅读兴趣排序。推荐卡片可展开查看排序依据。

## 新闻问答的 Key 与使用

每条通知右下角的“问问这条通知”打开 RAG 问答小窗。组员在弹窗的“DeepSeek 设置”填写自己的官方 API Key 后即可提问，无需下载本地大模型或安装新的向量数据库。Key 不包含在源码包里，也不要发到群聊、提交到 Git 或写入测试文件。

检索在本机进行，默认以当前通知为主并补充最多两条相关记录；可以取消“同时参考相关通知”。模型默认 `deepseek-flash`，依据 [DeepSeek 官方接口文档](https://api-docs.deepseek.com/) 配置。只有发送问题时才访问 DeepSeek，问题、近期对话和检索片段会随请求发出，并使用账户 API 额度。打开新闻弹窗不会触发调用。

默认启用“读取官网全文”：发送时读取当前及最多两条已收录相关通知的公开 HTML 正文，分段检索后回答。成功正文在本次会话缓存15分钟，可用“清除全文缓存”让下次发送重新读取。官网读取失败时会明确提示摘要/标题回退；附件正文暂不解析。展开“查看回答依据”可核对来源、内容层级、全文片段及读取时间。会话按新闻分开，关闭窗口后在本次浏览器会话中仍可继续；“清空本条对话”只清理该新闻。

## 分工与合并

首次 ZIP 交接适合大家拿到同一基线。开始多人改代码后，建议由组长建立私有 Git 仓库，邀请组员加入；仓库创建、邀请与上传由你们自行完成。只共享应用源码和已审阅的预置文件，不提交 `.env`、`.venv`、运行数据库、本地标注或 `artifacts` 中的打包与检查产物。提交前逐项核对将提交的文件。

可以按文件边界分工，减少同时改同一文件：

| 工作 | 主要位置 |
| --- | --- |
| 页面与交互 | `app.py`、`src/shu_insight/ui/` |
| 提取、分类、时间与摘要 | `src/shu_insight/processing/` |
| 推荐与关键词 | `src/shu_insight/ranking/`、`config/` |
| 来源解析与更新通路 | `src/shu_insight/sources/`、`src/shu_insight/ingest/`、`src/shu_insight/services/` |
| 验证与使用说明 | `tests/`、`README.md`、`docs/组员协作与运行.md` |

先约定每个人修改的范围，各自建分支、小批提交，由一人合并并运行检查后再交给全组。使用 ZIP 时，由一人维护主版本，组员交回自己改动的文件与说明，再统一合入；不要把多个完整文件夹互相覆盖。配置、数据库结构和公共数据模型的变更要提前同步给全组。

开发者额外安装依赖并验证：

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check app.py src scripts tests
```

测试完全离线，不证明官网当前可访问；官网状态以主动点击更新后的实际结果为准。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 找不到 `.venv\Scripts\python.exe` | 先在当前工程目录创建虚拟环境；不要复制别人的 `.venv`。 |
| `No module named shu_insight` 或 `streamlit` | 使用本说明中的完整 Python 路径，在工程根目录重新执行 `pip install -e .`。 |
| 提示不支持 Python 版本 | 使用项目支持的 3.11 或 3.12 重新创建环境。 |
| 网站是空库 | 停止应用，核对离线导入命令中的 manifest 和 database；确认没有遗留的 `SHU_NOTICE_DATABASE_PATH` 指向其他库。 |
| 8501 端口被占用 | 先停止旧进程，或将启动命令中的端口改为 8502，并打开 `http://127.0.0.1:8502`。 |
| PowerShell 阻止 `.ps1` | 使用上面的 Python 启动命令，不改执行策略。 |
| 更新失败但库存仍可看 | 按界面原因判断，库存不等于本轮在线检查成功；不要反复点击或绕过访问限制。 |
| 合并后仍像旧页面 | 在启动终端按 `Ctrl+C`，确认进入正确工程目录，再用该目录的虚拟环境重启。 |
