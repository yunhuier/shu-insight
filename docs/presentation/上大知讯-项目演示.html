数据挖掘流程

把网页里的通知整理成可计算的数据

程序读取官网 HTML，识别栏目与正文结构，再提取统一字段。

1

读取栏目

用户点击更新，
读取公开通知列表。

2

获取正文

跟随通知链接，
提取 HTML 正文。

3

结构化处理

清理杂项，提取日期、
主题、对象与摘要。

4

本地存储

SQLite 保存记录，
识别重复与内容变化。

5

推荐与问答

标签和画像排序，
需要时检索全文问答。

一条通知的字段
标题来源时间摘要标签适用对象原文链接

依赖各站页面解析规则，并非统一 JSON 接口。当前不解析 PDF 附件，缺失字段保留“未知”。

可以把这一步解释成把杂乱网页整理成一张表。采集是拿到材料，清洗和字段提取是让材料能被后面的算法使用。摘要和标签主要来自规则处理，不能讲成每条新闻都经过大模型生成。重复导入不会变成新的重复通知，用户点击才会更新。项目使用Python、Streamlit与SQLite。依据 README、ingest、processing、db 模块。

聚类

用读过的不同文章，归纳阅读兴趣

TF-IDF 表示文章特征，时间加权 K-Means 把相近内容聚在一起。

01

文章变成特征

使用标题、已收录摘要和标签，

02

从分组生成画像

近期首次阅读权重更高，
以最近点开文章所在簇归纳兴趣。

10 个预设画像 ＋ 1 个聚类画像
画像可以参与推荐的受众匹配。
这不是把10个用户聚类，而是把一个用户打开的不同文章按内容分组。每篇只保留首次打开记录，反复点同篇不会刷新其时间权重。样本少于10篇不可启用。TF-IDF可以解释为把文章转成一串能体现内容特点的数字，K-Means负责把相近的数字放到同一组。实现最多使用200篇，分2至4簇，样本时间权重30天减半、最低0.2。取最近首次点开的文章所在簇来归纳当前兴趣。图中的三组与12个点只是讲解示意。聚类画像未手选标签和关键词时，程序才会使用该画像的目标和代表词作为查询词。依据 profiles/learning.py、ui/personas.py、db/repositories.py。

02 / 读原文

HTML 全文分段

发送问题时读取原文，
把长通知拆成较短片段。

03 / 做检索

BM25 找相关段

提供最多五段证据。

04 / 生成回答

调用 DeepSeek

结合问题与检索片段，
给出带引用依据的回答。

可以展开回答依据，对照原文核实。原文未说明的内容，提示继续查看官网。

全文读取失败会明确退回已收录摘要或标题。问答需要可用网络和 API Key，幻灯片本身可离线播放。

RAG可以说成开卷回答：先找到与问题有关的资料，再交给模型组织语言。BM25是检索步骤，DeepSeek是生成步骤。这里不声称微调了大模型，也不是全网自由搜索。相关资料来自已收录通知范围。API Key只在演示前自行配置，不能出现在投影里。现场选择有HTML正文的一条通知，问题以对象、流程、材料为主，最后展开证据。无材料就不能声称检索到了答案。依据 services/notice_qa.py、services/notice_fulltext.py、ui/notice_qa.py。
